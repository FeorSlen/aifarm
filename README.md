# aifarm

Ферма Google AI Mode: FastAPI-шлюз с нативным **MCP-сервером** + воркеры на
анти-детект браузере (Camoufox), общение через RabbitMQ.

```
MCP client ──HTTP──> gateway ──AMQP──> worker ──Camoufox──> Google AI Mode
```

## Запуск

```bash
cp .env.example .env          # задать RABBITMQ_PASSWORD
docker compose up -d --build
curl -s localhost:8000/health # {"status":"ok"}

claude mcp add --transport http aifarm http://localhost:8000/mcp
```

Инструменты MCP: `search` (вопрос → ответ AI Mode, блокирующий), `my_searches`
(список вкладок), `close` (закрыть вкладку). `tab_id` из ответа `search`
передаётся обратно, чтобы продолжить тот же диалог.

**Вложения.** Картинки и файлы можно приложить и к первому вопросу беседы, и к
продолжению. Файл сначала загружается в шлюз, в ответ приходит `file_id`:

```bash
curl -s -F file=@photo.png -H 'X-Aifarm-User: <uuid4>' localhost:8000/files
# {"file_id":"…","name":"photo.png","size":42262,"kind":"image"}
```

Затем `search(question, file_ids=[…])` — новая беседа, или
`search(question, tab_id, file_ids=[…])` — продолжение. Сообщение — любая
комбинация текста, картинок и файлов; новая беседа начинается с текста, в
продолжении при вложениях `question` может быть пустым.

Первый вопрос с вложениями идёт через плашку AI Mode на главной: файлы
прикрепляются там же и уходят с вопросом одним сообщением. Если плашка не
сработала или главная файлы не приняла, вопрос уходит обычным путём, а
вложения — следующим сообщением после ответа; клиент получает ответ на него. Картинки
(avif/bmp/jpeg/png/webp/heif/heic) уходят в поле картинок AI Mode, остальное —
в поле файлов. `file_id` привязан к арендатору (`X-Aifarm-User`) и живёт
`AIFARM_UPLOAD_TTL_S`.

`search` возвращает `{tab_id, answer, sources}`: ссылки, проставленные Google в
ответе, помечены в тексте маркерами `[1]`, `[2]`… и расшифрованы в `sources`
(`index`, `url`, `title`). Источники читаются из уже отрендеренной разметки
ответа, без кликов по UI Google; если разметка поехала, остаётся один текст.

## Публичный доступ (VPS)

```
GATEWAY_BIND=0.0.0.0:8000
AIFARM_MCP_HOST=0.0.0.0        # выключает DNS-rebinding guard
```
Аутентификации у сервера нет — только за файрволом (`ufw allow from <ip> to any port 8000`).

## Прокси

Без резидентного/мобильного прокси Google банит IP датацентра (`/sorry/`).
```
PROXY_URL=http://user:pass@host:port     # sticky-эндпоинт, ротация IP на стороне провайдера
```

## Тёплые куки

Холодный профиль + свежий IP = reCAPTCHA почти всегда. Куки живого браузера
резко снижают частоту. Экспорт: расширение Cookie-Editor (JSON) или
`Get cookies.txt LOCALLY` (Netscape). Положить файл и указать:
```
GOOGLE_COOKIES_FILE=/app/cookies.txt     # . смонтирован в /app
```
Залогиненные куки (`SID`, `SAPISID`, `__Secure-1PSID`…) убирают капчу почти
полностью, но **привязывают аккаунт к трафику фермы** — риск блокировки
аккаунта. Лучше левый аккаунт или только `NID`/`SOCS`/`AEC`/`DV`.

## Личность профиля

Каталог профиля хранит две вещи: куки (`cookies.sqlite`, ведёт сам Firefox) и
устройство (`device.json`, пишем мы при первом запуске профиля). Дальше
устройство только читается и передаётся в Camoufox как `config=` — внутри него
`merge_into` ставит лишь отсутствующие ключи, поэтому сохранённое железо
побеждает генерацию.

Без этого файла Camoufox честно делает то, что обещает в документации —
«infinite unique fingerprints»: `fingerprint=None` и `os=None` означают новую
машину на каждый запуск, вплоть до смены ОС. Один и тот же cookie jar,
возвращающийся то с Windows, то с macOS, — противоречие внутри одной личности,
и на общем адресе (мобильный CGNAT, где профилей за одним IP много) это
становится главным сигналом.

География в `device.json` НЕ попадает: `locale:*`, `timezone`, `geolocation:*`
каждый запуск считает `geoip` по текущему exit-IP. Устройство постоянно, адрес
и география — согласованы между собой. Проверка обоих свойств, без обращений к
Google:

```
docker compose run --rm -e DISPLAY=:99 worker \
    sh -c 'Xvfb :99 -screen 0 1920x1080x24 -nolisten tcp & python scripts/check_device.py'
```

Профиль меняется не только после `/sorry/`, но и планово — отработав
`AIFARM_PROFILE_MAX_QUERIES` вопросов (норма берётся с разбросом ±2, чтобы смена
не приходилась на круглое число). Плановая смена маркер не ставит. Проверяется
она только перед новым поиском: follow-up обязан остаться на своей вкладке.
После любой смены `tab_id` прошлой личности недействительны.

## Ручной прогрев профилей

Профили хранятся локально в `protected profile/profile/user1…user10`; каталог
игнорируется Git. Открыть профиль для ручной проверки:

```bash
python scripts/warm_profile.py 1
```

При `/sorry/` worker ничего не удаляет: кладёт в профиль маркер
`.needs_attention` со временем блокировки и переключается на следующий. Профиль
с куками остаётся на диске и через `AIFARM_PROFILE_COOLDOWN_H` часов сам
возвращается в ротацию (маркер снимается при выборе). Если остыть не успел
никто — берётся тот, что отдыхал дольше всех, ротация не останавливается.
Заблокированный запрос не повторяется автоматически.

Пустой маркер (`touch .needs_attention`) держит профиль вне пула бессрочно —
так профиль ставится в очередь на ручной прогрев; `warm_profile.py` предложит
снять маркер. Когда все профили выведены такими маркерами, MCP возвращает
`human_action_required`.

Смотреть за браузером на VPS можно по VNC (Xvfb `:99`, x11vnc на 5900):

```bash
ssh -L 5900:127.0.0.1:5900 root@VPS_IP   # и открыть localhost:5900 в VNC-клиенте
```

`VNC_BIND=0.0.0.0:5900` публикует порт наружу — x11vnc поднят с `-nopw`,
так что это доступ к живым Google-сессиям без пароля; только под файрволом.

## Известные ограничения

- `_next_proxy()` — один sticky-эндпоинт из `PROXY_URL`, пула нет.
- Один воркер: `Gateway` хардкодит `WORKER_ID`; для нескольких нужен роутинг.
- Google `/sorry/` reCAPTCHA не решается — только обход куками/прокси.
- Длинный промпт уходит в поле Google одним `fill()`, вручную допечатываются
  последние `HUMAN_TAIL_CHARS` символов. Посимвольный ввод всей простыни давал
  сотни XHR в `/complete/search` и минуты стука по клавиатуре — это и жгло профили.
  Верхний предел длины запроса у самой Google-строки не проверен.
- Денойз: структурный стрип; фильтр UI-строк по локалям не доделан (`sup` под вопросом).
